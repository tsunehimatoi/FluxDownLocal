# FluxDown 精简版：产品边界与维护准则

> 本文是本维护分支的产品需求基线。出现功能取舍、上游合并冲突或实现歧义时，以本文为准；实现事实仍以源码为准。

## 1. 产品定位

FluxDown 精简版是一个**本地优先、专注下载、低干扰**的多协议下载器。目标不是复刻上游的全部平台和商业服务，而是在不牺牲下载速度、稳定性、协议兼容性与自动化能力的前提下，删除与下载无关的云端、运营、扩展平台和复杂悬浮交互。

判断一项功能是否应保留时，依次回答：

1. 它是否直接提高下载速度、成功率、协议兼容性或任务管理效率？
2. 它是否属于用户明确依赖的输入通道，例如 RSS、浏览器接管、aria2 RPC？
3. 它是否可以完全本地运行，或只连接用户明确配置的服务？
4. 删除它是否会让核心下载链路退化？

前两项任一为“是”的功能通常保留；仅用于账号、运营、推广、遥测或官方云协作的功能移除。

## 2. 必须保留的核心能力

| 范围 | 保留内容 | 原因 |
|---|---|---|
| 下载引擎 | HTTP/HTTPS、FTP、BitTorrent、磁力、eD2K、HLS/DASH | 产品主体 |
| 性能 | 动态分段、断点续传、并发控制、连接上限、代理、速度限制、本地多 CDN 节点优化 | 直接影响速度、稳定性或成功率 |
| 任务管理 | 新建、暂停、继续、失败重试、队列、分类、计划下载、完成后动作、清理已完成任务 | 下载器基本能力 |
| 自动化 | aria2 兼容 RPC、REST/MCP、RSS 订阅、用户脚本 | 无人值守与外部接入能力 |
| 浏览器集成 | Chrome/Edge/Firefox 下载接管、右键下载、磁力接管、Native Messaging、下载中数量角标 | 核心输入通道 |
| 本地数据 | SQLite 持久化、导入导出、日志、崩溃恢复 | 可靠性与可维护性 |
| 自建服务 | 用户主动配置的 headless server 或远程下载地址 | 属于用户控制的基础设施，不是 FluxDown 官方云 |
| 关于页 | 软件名称、版本、开源许可、必要的本地构建信息 | 关于页本身保留，只删除云服务和推广内容 |

### 多 CDN 的边界

多 CDN 是下载引擎在本地解析同一资源的多个可用节点并调度连接的性能功能，不等于 FluxDown 官方 CDN 服务。只要它不依赖官方配置下发、遥测上报或账号体系，就应保留。

## 3. 明确移除且不得回归的内容

| 类别 | 移除内容 |
|---|---|
| FluxDown 官方云 | 登录、注册、官方账号、设备云同步、远程任务云同步、云配置、官方 CDN 配置下发 |
| 数据上报 | 遥测、部署统计、下载统计上报、设备身份、昵称池、CDN 健康或贡献上报 |
| 运营入口 | 内置反馈上传、QQ群/社区推广、捐赠、官网导流、商店推广、无关外链 |
| 在线更新 | 自动检查更新、后台更新器、下载并替换程序、更新弹窗 |
| 应用内“扩展” | JS/`.fxplug` 插件市场、安装、启停、设置页及相关产品入口 |
| 复杂悬浮交互 | App 或浏览器中的悬浮球、页面浮动按钮、页面资源面板（App 悬浮球仍是待删除技术债） |
| 浏览器资源嗅探 | DOM 媒体扫描、MutationObserver 资源收集、Fetch/XHR monkey patch、HLS/DASH 清单嗅探、资源预览与批量资源面板 |

### 术语必须区分

- **“扩展功能”**：应用内 JS/`.fxplug` 插件系统。它不属于精简版产品，应移除。
- **“浏览器扩展”**：Chrome/Edge/Firefox 的下载接管插件。它是核心能力，必须保留。
- **“组件”**：下载链路可能需要的本地辅助程序。只要直接服务下载能力，就不能因名称相似而误删。

底层若仍存在未暴露的旧插件类型、兼容代码或数据库字段，只能视为待清理的技术债，不能据此恢复 UI、API 或联网入口。删除残留前必须确认不会影响下载主链路。

## 4. 浏览器扩展约束

浏览器扩展应保持接近成熟下载接管插件的简单事件模型，不自行发明会重放下载的冷启动机制。

必须满足：

- 只接管浏览器真实创建的新下载，不扫描或重建历史下载记录。
- 浏览器启动时不得批量重新发起、恢复或复制未知下载。
- 发送给 FluxDown 成功后，浏览器自身不得继续下载同一文件。
- 冷启动、Native Messaging 暂时不可用或设置未加载时，必须安全失败；不得形成“取消—重建—再次拦截”循环。
- 保留磁力链接点击接管，但实现只能监听 `magnet:` 点击，不得顺带扫描页面资源。
- 角标显示 FluxDown 中真正处于下载状态的任务数量，不显示嗅探资源数量。
- 图标可以保留状态动画与现有配色，但不得为动画引入资源嗅探或高频页面注入。

## 5. 无人值守与交互规则

- 启用“跳过二次选择/免打扰”后，通过 aria2 RPC、RSS 或其他无人值守入口创建的磁力/种子任务不得再弹 BT 文件选择框。
- RSS 是核心功能，不能因精简云服务或应用内插件而删除。
- “清空已完成任务”位于主界面标题栏，使用垃圾桶图标，不弹确认框；是否显示由“标题栏按钮”设置控制。
- 关于页保留，但不显示浏览器插件推广、官方云服务、在线更新、反馈上传或其他多余信息。
- 任何确认框、动画或后台任务都不能拖慢任务创建与下载热路径。

## 6. 网络与隐私契约

默认运行时只允许以下联网行为：

- 用户创建的下载请求及其协议所需流量；
- BT tracker/DHT、eD2K server/Kad、RSS 地址等协议必需或用户配置的流量；
- 用户主动配置的代理、DoH、tracker 订阅、自建服务器或远程下载地址；
- 用户主动触发的 ffmpeg、yt-dlp 等下载辅助组件安装或版本查询；
- 用户主动触发的链接打开行为。

禁止静默连接 FluxDown 官方账号、配置、更新、遥测、反馈或 CDN 控制服务。新增任何默认外联前，必须在代码评审中列出域名、触发条件、发送数据、关闭方式和对下载核心的必要性。

## 7. 上游同步规则

从上游 `git pull`、merge 或 cherry-pick 后，优先保护下载引擎修复和协议兼容性，同时审计是否重新引入下列内容：

- cloud/auth/sync/analytics/feedback/update/updater；
- plugin market、`.fxplug` UI/API；
- 浏览器 resource sniffer、floating button、resource panel；
- 关于页、设置页或侧栏中的推广和云入口；
- 新的默认外联域名或后台定时请求。

不要为了减少冲突而恢复已删除功能。确实需要采用上游实现时，只移植与下载核心直接相关的最小部分。

## 8. 验收清单

每次发布精简版至少确认：

- [ ] 冷启动后没有账号、遥测、反馈或更新请求。
- [ ] Windows 安装目录不包含 `fluxdown_updater.exe`。
- [ ] App 与 Web 设置页没有云账号、插件市场、反馈或自动更新入口。
- [ ] 关于页仍可查看版本和许可，但没有浏览器插件推广及云服务内容。
- [ ] RSS、aria2 RPC、浏览器下载接管、磁力接管均可用。
- [ ] aria2/RSS 无人值守 BT 任务遵守跳过二次选择设置。
- [ ] 浏览器扩展包不包含资源嗅探、页面悬浮球、Fetch/XHR 注入脚本。
- [ ] 浏览器启动不会重新创建历史或未知下载。
- [ ] 多 CDN、动态分段、代理和断点续传没有因精简而退化。
- [ ] Windows 安装包与浏览器扩展均由当前源码重新构建并记录哈希。

## 9. 当前实现说明

本分支已移除主要云服务、遥测、反馈、更新器、插件产品 UI，以及浏览器资源嗅探和悬浮资源界面。当前仍有两类已知技术债：未暴露的旧插件引擎/API 类型，以及 App 自身的悬浮球实现与设置。它们不属于目标产品面，后续应逐步删除，但必须以“不影响下载速度、协议和稳定性”为前提。设置搜索中若仍残留已删除功能的关键词，也应一并清理，不得把残留入口误认为功能仍应恢复。
